# k3 — Legion vs. the 18-repo practice corpus: comparison & recommendations

**Date:** 2026-08-13 · **Author:** Legion (orchestrated analysis)
**Baseline A (live system):** `tools/skills/legion/doctrine/*.md` (compact tier model + scope rule) and workspace `docs/agent-rules/legion.md`.
**Baseline B (plan):** `tools/skills/legion/docs/research/2026-08-12-legion-architecture-book-final.md` (2,206 lines, read in full) — G-A1…G-A27, phases TAILOR→FREEZE, `OBJECTIVE × DEPTH × RIGOR`, state v2, Arcane guards, terminal states, eval plan, adoption sequence.
**Corpus:** 18 repos at `/tmp/legion-practices-sources.GtrSei` (SWE-AF `-snapshot` duplicate excluded).

## Method & evidence honesty

Five parallel mining agents covered the corpus by group. Three full reports landed (core-workflows, reasoning-context, assurance). The harness miner died once on a transient model-auth error and was resumed to completion; the platform/catalog miner died twice (auth error, then runtime abort) — its claude-code findings are instead grounded in the **book's own Appendix A.5 source notes**, which already cite the exact claude-code mechanisms absorbed. Three reports arrived with middle sections truncated in transit; the neolab/trailofbits/testdino sections were recovered by targeted re-request. Sections not recovered (obra-superpowers detail, coderabbit detail, the three discovery catalogs) are covered from the book's A.4 M1–M12 matrix + A.5 citations and are flagged where used. Machinery defects are recorded per G-A27 in the appendix; analysis continued.

## Verdict

The final book is **directionally complete and corpus-convergent**: the strongest mechanisms in the corpus independently converge on what G-A7/G-A13/G-A18…G-A27 already specify (revision caps, satisficing, severity floors, scoped re-review, decide-with-debt, decision finality, door-scaled ceremony, spike-over-debate, scoped invalidation, loop self-detection, bounded divergence, gate decisiveness). **Nothing structural should be removed from the plan.** The corpus contributes ~20 genuinely new *mechanisms* (mostly enforcement plumbing and anti-injection defenses the plan lacks), ~12 sharpenings of existing doctrines, and a clear anti-pattern list the plan correctly excludes. **The largest risk is not design — it is the implementation gap:** live doctrine files are 30–50 lines each and contain none of the G-A machinery (`open_questions == []` is still the live Sage predicate; no acceptance ledger, no intent epochs, no lineage budgets, no architecture schemas, no architecture evals).

Decide the canonical home per concept before Part XVI step 1 ("freeze canon") — recommendation: `docs/agent-rules/` owns the *workspace constitution*, `doctrine/architecture/**` owns the *architecture method*, and each side references — never duplicates — the other.

# Q3 — Genuinely missing practices to ADD

Ranked within each group. Each item: mechanism → where it lands in Legion.

## Group A — Convergence-layer enforcement plumbing (highest value)

- **A1. Dismiss-first intake gate for all review findings** — trailofbits `plugins/vulnerability-triage-brocards/`: 7 falsifiable brocards ("No Vulnerability Without a Threat Model", "No Exploit from the Heavens", "No Cure Worse Than the Disease"…), verdicts `DISMISS / NEEDS-MORE-INFO / ACCEPT`, stop at first DISMISS, every dismissal records its brocard #. → Front-end to G-A13/G-A20: a finding must survive dismissal *before* it may consume a review round. Kills FP noise at the source instead of filtering it later.
- **A2. Zero-inspection = FAIL, plus known-bad-fixture self-tests for every gate** — trailofbits root `AGENTS.md`: "A checker that inspects zero items must fail, not pass"; validators ship `--self-test` that builds a known-bad fixture and asserts rejection. → Arcane guards + Part XIV evals: every hard guard in §31 gets a fixture that must trip it. A gate that can't fail is theater.
- **A3. Anti-sycophancy packet rule** — addy `skills/doubt-driven-development/`: the reviewer receives **ARTIFACT + CONTRACT only, never the CLAIM**; plus a "doubt theater" detector (2+ cycles, 0 actionable findings → stop and escalate). → Covenant/Oracle packet contents (book has immutable packets; this governs *what's inside* them).
- **A4. Behavioral stuck-loop detectors with exact numbers** — SWE-AF `swe_af/execution/coding_loop.py` `_detect_stuck_loop` (window-3 repeated-fix heuristic), `prompts/qa_synthesizer.py` ("same test failing 3+ times; oscillating between two approaches"), `level_failure_abort_threshold=0.8`; addy TDD skill ("same test command twice with no intervening code change"). → Arcane §31 guards: the fingerprint guard catches *semantic* loops; these catch *behavioral* loops fingerprints miss.
- **A5. Submission-by-observation** — mini-swe-agent `environments/local.py:45-56`: first stdout line == exact sentinel **and** `returncode == 0` ⇒ `Submitted`. Completion is an observed environment fact, ungameable by prose. → Ambient-tier completion checks and Alchemist's `CANDIDATE` minting: one deterministic sentinel where full receipt plumbing is overkill.
- **A6. killpg-enforced per-action timeouts** — mini-swe-agent `local.py:72-92`: every action an independent `subprocess.run`, `timeout=30` default, `os.killpg(SIGKILL)` on expiry so no orphaned children survive. → G-A23's "hard time boundaries" need exactly this subprocess-group discipline in worker scripts.
- **A7. Storage-enforced terminal-state machine** — agentfield: run status transitions enforced at the *persistence layer* with an explicit transition map and typed rejection errors; `timeout` is retryable-non-terminal (`timeout→{running,cancelled}`) vs `failed` terminal; one canonical status enum with alias folding at the boundary. → Arcane run ledger: terminal states stop being doctrine and start being unrepresentable illegal transitions.
- **A8. EXIT-gate sentinel contracts** — gstack ship: the gate verifies an exact final-line contract; no "if applicable" escape. → Legion terminal-state receipts + SubagentStop discipline: closure is a string-matchable fact.
- **A9. Event history + replay on the receipt log** — agentfield control plane owns durable event history and replay; data plane owns effects. → Arcane receipts: enables after-the-fact proof of "what fired when" without new authority.

## Group B — Memory-integrity & injection defenses (Legion has none today)

- **B1. Render-boundary defense for rehydrated state** — gstack `datamark()`: state/decisions/receipts loaded back into context are wrapped so they can never render as instructions. → Crypt memory reads, Membrane packets, resumed sessions. **This is the resurfacing twin of G-A22's resumption guard** — stop precedence means nothing if a rehydrated goal can re-enter as an imperative.
- **B2. User-origin gate for preference/profile writes** — gstack: preference writes accepted only from the user's own message, never from tool output. → Crypt memory + any `learn`-style capture: profile-poisoning defense aligned with "authority is never inferred."
- **B3. One-way-door 3-layer classifier** — gstack: declared `door_type` → skill-category set → keyword net → **default-safe** (ambiguous ⇒ treated one-way); learned preferences may never suppress a one-way classification. → Arcane's classified-effect gating and Part IV's door rule get deterministic classification machinery instead of judgment.
- **B4. Untrusted-content typing of test artifacts** — testdino: trace.zip contents (DOM, headers, cookies) are secret-bearing and prompt-injection risks — redact before sharing, treat content as untrusted. → G-A25 evidence handling: acceptance-surface artifacts carry a trust label.


## Group C — Review & assurance upgrades

- **C1. Five-verdict taxonomy with survivor-only severity** — trailofbits `c-review-fp-judge.md`: `TRUE_POSITIVE / LIKELY_TP / LIKELY_FP / FALSE_POSITIVE / OUT_OF_SCOPE`; severity attaches **only** to TP/LIKELY_TP survivors; determinism rule ("the same finding must not be LIKELY_FP in one run and TP+LOW in another" — hardening gaps are always TP+LOW, never LIKELY_FP). → G-A13's kind×severity gains a verdict layer in front of it; informational findings never enter the blocking economy.
- **C2. Threat-model-relative severity** — same source: the same bug is CRITICAL under `REMOTE`, LOW/OUT_OF_SCOPE under `LOCAL_UNPRIVILEGED`. → Oracle security findings: severity is meaningless without the declared threat model; add `threat_context` to the finding schema.
- **C3. Named-gate rejection format** — trailofbits `gate-reviews.md`: six gates (Process, Reachability, Real Impact, PoC Validation, Math Bounds, Environment); any fail ⇒ `FALSE POSITIVE — Gate 5 (Math Bounds): validation at line 98 ensures…`. → G-A20 already requires IDs + minimum correction for *blocks*; this adds the symmetric requirement for *rejections*: auditable, gate-named, evidence-cited.
- **C4. Breadth/filter separation** — trailofbits root `AGENTS.md` + coderabbit: never tell a reviewer to pre-filter; report everything with severity attached, filter in a separate pass whose parameter has **no silent default**. → Oracle/Covenant dispatch contracts.
- **C5. Adaptive reviewer gating + pre-emit existence verification** — gstack review: `GATE_CANDIDATE` files clean 10 consecutive runs ⇒ skip gate; `NEVER_GATE` insurance classes; every finding's cited file/symbol is verified to exist before emission. → Cost-routes review muscle and deletes an entire hallucinated-finding FP class before it reaches a human.
- **C6. Judge hygiene rules** — neolab `agents/judge.md`: reasoning FIRST then score; default-low ("anything higher requires specific, cited evidence"); essential-checklist NO caps the total; anti-anchoring (generate your own reference before reading the artifact); explicit bias table (length, sycophancy, authority, completion, anchoring). → Oracle evaluation mechanics; hard-gates-before-scores is G-A10, this is the judge-side half.
- **C7. Criteria frozen across retries** — neolab do-and-judge: "changing the criteria mid-task invalidates the comparison across attempts"; criteria-setter never re-run or re-tiered mid-task. → Codifies G-A19/G-A20 *inside* fix loops: judge spec seals at dispatch; only the implementation changes.
- **C8. Confidence display bands + fingerprint dedup + multi-source boost** — gstack review (7+/5–6/3–4/1–2 display gates; same-fingerprint dedup; independent sources raise confidence). → Oracle finding presentation hygiene.
- **C9. Two-axis parallel review, never merged** — mattpocock code-review: Standards and Spec as separate sub-agents "so they don't pollute each other"; "do **not** merge or rerank findings." → Covenant parallel seat design.

- **D4. Failure taxonomy with a reproducible diagnostic per class** — testdino: Timing/Async, Test-Isolation, Environment, Infrastructure, each bound to a diagnostic (`--repeat-each=20`, `--workers=1`, CI-vs-local trace diff, Docker repro); type the failure BEFORE fixing. → G-A21's observed-failure repair route.

Numeric tolerances frozen pre-run** — testdino `core/visual-regression.md` (`maxDiffPixelRatio: 0.01` pages, `maxDiffPixels: 10` components, zero-tolerance carve-outs); a11y as `expect(violations).toEqual([])` with `disableRules([...])` permitted **only** as a named, enumerated migration allowance. → G-A19: tolerances and escape hatches are frozen ledger items, not post-red negotiations.

Negative-trigger evals** — lambdatest `evals/`: "skill should NOT activate for pure API testing" cases — activation *precision* is tested, not assumed. → `evals/routing.jsonl`: prove ambient-tier work does NOT invoke contract machinery (the anti-ceremony tripwire the incident record demands).
- **D8. Enforcement-typing on every check** — lambdatest: declare up front when a check *cannot* gate (informational-only). → Membrane typed degradation made structural: `gates: true|false` required field; no pretending a dashboard gates a build.
- **D9. Weighted severity score + "Needs Review" bucket** — lambdatest accessibility playbook: published weights (Critical 1.0/Serious 0.75/…), machine-certain findings separated from ambiguous ones. → Ambiguous findings never block and never vanish — they land in a triage bucket with an owner.

## Group E — Budget & runtime semantics

- **E1. Wall-clock as a separate, non-liftable budget class** — mini-swe-agent `agents/interactive.py:75-95`: `TimeExceeded` is never re-promptable (re-querying would loop forever); cost/step budgets may be lifted **only by live human input**; unattended runs at the cap must die cleanly with the trajectory saved. → G-A23 refinement: time and money are different axes with different lift rules.
- **E2. Forced submission at every cap + `min_budget_for_new_attempt` + 1.1× hard-stop band** — swe-agent `sweagent/agent/agents.py` (book A.5 + harness miner): autosubmit best current state at each cap with a labeled exit status; a new attempt requires minimum remaining budget; retries spend a shared envelope. → `BUDGET_STOP` gains partial-credit semantics for reversible work: submit-best-and-label instead of stopping empty (book already allows "best justified route with explicit risk" — this mechanizes it).
- **E3. Retry-requires-cap lint + retryable-class whitelist** — lambdatest `validate-config.js`: `retryOnFailure: true` without `maxRetries` is a lint warning; retry only for actionable config/environment classes; mini-swe-agent's tenacity config carries an explicit `abort_exceptions` list (auth, context-window, not-found — never retried). → "No unbounded execution" becomes statically checkable.
- **E4. Model-tier earned-trigger table** — neolab Model Selection Policy: tiers *earned, never defaulted*; exhaustive strong-tier trigger list (auth, payments, data integrity, irreversible migration, public-API break, concurrency); **mechanical-breadth carve-out** ("renaming a symbol across 40 files is not opus"); tie-break to the cheaper tier because "escalation makes a cheap first guess recoverable." → Legion's "cheapest capable executor" / Terra-vs-Luna routing becomes an enforceable table instead of a vibe.
- **E5. Per-tier default timeout calibration** — agentfield's 2h `default_execution_timeout` is far too loose; mini's 30s per-action is right-sized. → When G-A23 lands, ship an explicit per-tier/per-depth defaults table instead of inheriting tool defaults.


## Group F — Decision, ownership & migration doctrine

- **F1. First-fix owner ≠ canonical owner (five-field record)** — instructa `architecture-ownership`: runtime-owner vs first-fix vs canonical owner are different facts; fix at the runtime-owner layer ambiently, record canonical owner + cleanup direction, do **not** re-architect mid-task. → Operationalizes G-A9 PATCH scope: local fix without reopening architecture, without pretending the patch layer is the rightful owner.
- **F2. Hard-cut rule set** — instructa `hard-cut`: one canonical codepath; delete the losing owner; **no rejection tests for old shapes**; **existence ≠ compatibility obligation**; named-boundary exceptions require exact file+function+reason. → Alchemist migration contracts; fits receipt culture.
- **F3. Test-placement doctrine** — instructa: an invariant's test lives at the **lowest owning layer** in the canonical suite; "never choose end-to-end to compensate for uncertainty"; duplicates merge into the strongest location. → G-A21 verification obligations; prevents regression-test sprawl.
- **F4. Prove-intent-before-fix + hidden-write suspects** — instructa `root-cause-finder`: "do not make the contract more permissive unless you can prove the observed payload is intended"; observers, lifecycle hooks, retries, background jobs are "suspects until proven intentional"; find the *first unintended side effect*. → Sage diagnose route; arms Oracle's never-certify-own-fix.
- **F5. ADR worthiness tri-gate** — mattpocock `ADR-FORMAT.md`: an ADR only when ALL THREE hold — hard to reverse + surprising without context + real trade-off; "if any of the three is missing, skip the ADR." → G-A15 gains an admission test so the ADR store doesn't bloat (book cites the idea in M6/M7 but never states the gate).
- **F6. Out-of-scope concept store** — mattpocock `triage/OUT-OF-SCOPE.md`: one file per rejected *concept*, "Prior requests" append-list, matched by concept similarity; **never record "already implemented" wontfix** ("would poison the dedup checks with false rejections"); rulings never graduate — return only as a fresh effort, not a resumption. → G-A19/G-A20: reviewer-proposed scope gets a durable, dedup-able rejection memory.
- **F7. Decision-map discipline** — mattpocock wayfinder: the map is "an index, not a store — a decision lives in exactly one place"; fog-of-war test ("ticket when the question is sharp; not-yet-specified when you can't phrase it sharply"); claim-before-work; one ticket per session; tickets sized to one ~100K-token session. → Sage's question/deferred-item management; session-sized work units.
- **F8. Duplicate-ownership audit taxonomy** — instructa: four buckets with a do-not-flag list for legitimate boundary adapters. → Turns G-A24's "one shared-state writer" from invariant into an audit procedure that won't false-positive.
- **F9. Event-sourced decision log semantics** — gstack `decisions.jsonl`: supersede/redact as invalidation-with-cause; active state computed, never mutated in place; entries carry scope/source/confidence. → Crypt/ADR store mechanics under G-A8/G-A9.

## Group G — Clarification & prototype capture

- **G1. Checkable clarification stop-rule** — addy `interview-me`: confidence-numbered hypotheses (<70% requires a stated reason); stop when you can *predict the answers to the next 3 questions*; hollow-yes detection ("whatever you think" = delegation, not decision). mattpocock `grilling`: ask the whole frontier per round, each question **with a recommended answer**; "finding *facts* is your job, never the user's" (dispatch sub-agents); done when the frontier is empty; "do not act on it until the user confirms." → Legion's "ask only for missing private input / destruction / reserved decisions" gains a convergence test: clarification is a loop with a stop predicate.
