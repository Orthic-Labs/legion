# Routing stub — frontend design and review

**For frontend qualitative critique, polish, visual/UX craft, and micro-interaction design review, use `/designer`.**

**For rendered-state enumeration, capture, coverage, and regression evidence, use `/audit-visual`; for functional/browser/runtime checks, use `/qa`.**

**For building new marketing sites, landing pages, or non-app web pages from scratch, use `/designer`.**

This file is a routing stub only. The canonical instructions for:

- Qualitative task cognition, hierarchy, ecommerce, Gestalt, craft, & Peak-End review → `/designer`
- Accessibility execution, WCAG checks, interaction behavior, & browser/runtime checks → `/qa`
- Rendered-state coverage & regression evidence → `/audit-visual`
- Website signature mechanism, anti-template gates, page workflow → `/designer`
- Production frontend component code (React + Tailwind, distinctive aesthetics) → `/designer`

> `/designer static` does not own interactive frontend work. If you landed here from a `/designer static` invocation with a
> web page or frontend review request, stop and route to the correct capability above.
