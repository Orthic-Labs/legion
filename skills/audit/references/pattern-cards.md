# Semantic pattern cards v1

These cards sharpen existing lenses; they do not add domains or replace frozen-plan triggers. The native reasoning packet includes cards only for their owning lens. Applicability is a fit guide, while `triggerEvidence` identifies the local signal to inspect. Every finding needs the listed source trace and must name evidence that would falsify it. If the trace is unavailable or ambiguous, report `unknown`; do not turn absence of evidence into a finding or a clean result.

| Card / owner | Applicability & trigger | Required trace | Falsifier / paired negative | Paired positive |
|---|---|---|---|---|
| `return-key-consumer-migration` / correctness | Serialized object, endpoint, RPC, SQL view/function, or table shape; a diff removes or renames a prior output key/column. | Compare old/new shape; trace old-key readers through repository callers, RPC names, and endpoint routes; record untraced boundaries. | All consumers migrate or disappear in the same change; new payload; never-serialized field. | Endpoint renames `accountId` to `ownerId` while a traced client still reads `accountId`. |
| `interactive-state-derived-output` / correctness | React/Vue/Svelte or equivalent interactive state; user action changes state while a related output is computed. | Follow handler state writes to dependent output, filters, summaries, alerts, and submit payloads. | Output is intentionally independent, or documented seed/default is correctly merged. | A selection control changes state while its alert list still reads a separate static list. |
| `upsert-replay-workflow-state` / data-safety | App/SQL upsert, on-conflict, or merge writes a literal to a workflow field (`status`, `stage`, `state`, `phase`, `tier`, `role`). | Inspect conflict columns/guards and relevant helper, trigger, or generated-column behavior. | Duplicate ignored, state omitted from updates, or update constrained to a safe current state. | Replay resets an advanced order to `pending`. |
| `migration-later-object-order` / data-safety | Timestamp-ordered SQL migration references an object declared elsewhere. | Resolve referenced objects through migrations and transitive includes; compare apply order; check guaranteed baselines. | Object comes from an earlier/same migration, guaranteed baseline, built-in, or extension. | Migration 020 creates a policy using a column first added in migration 030. |
| `postgres-definer-searchpath-and-public-execute` / security | PostgreSQL/Supabase `SECURITY DEFINER` function, especially when path or grants change or rely on defaults. | Read full body and fixed `SET search_path`; trace effective `EXECUTE` ACL, untrusted caller reachability, and documented intended roles. | Resolution is pinned and access matches an evidenced audience. `PUBLIC` execute alone is not a defect without a conflicting policy. | Untrusted callers can execute with caller-influenced resolution, or `PUBLIC` retains execute contrary to an evidenced private policy. |
| `supabase-single-missing-row-response` / correctness | Supabase/PostgREST JS/TS `.single()` query may return zero rows for a request-derived key. | Trace key origin, query cardinality/prior existence proof, returned `{data,error}` handling, and response mapping. Distinguish returned result errors from thrown exceptions. | `.maybeSingle()` maps absence intentionally; row existence was proved; or PGRST116 maps to not-found. | Request lookup returns PGRST116 but handler maps result to 500. |
| `qualified-function-create-unqualified-comment` / data-safety | PostgreSQL/Supabase migration creates and comments on a function. | Compare schema and argument signature; inspect migration/session `search_path` for the COMMENT statement. | Matching qualified names, established unqualified convention, or statement-scope path pins the right schema. A function body's own `SET search_path` does not set migration-session scope. | `CREATE FUNCTION public.refresh()` followed by unqualified `COMMENT ON FUNCTION refresh()` without a migration-level path. |
| `environment-read-before-config-loader` / correctness | Node.js JS/TS module captures `process.env` during evaluation. | Trace entry/import order, environment loader, captured value, and its consumer. | Lazy read after loading, dynamic import after setup, or documented build-time constant. | Entry imports client before `loadEnvFile`; client captures `API_URL` at module top level. A top-level read alone is not a defect. |
| `react-render-state-and-eager-initializer-effects` / correctness | React JSX/TSX render setter or nontrivial eager `useState(expr)`. | Trace setter scope and guard; establish repeated cost/effect of eager expression; inspect lazy initializer purity. | Setter is in handler/effect/callback or provably guarded derive-state path; initializer is cheap/pure or expensive work is lazy. | Setter runs unconditionally in render, or `useState(parseLargePayload())` repeats parsing each render. |
| `promise-all-independent-partial-effects` / performance | JS/TS `Promise.all` combines independent writes/sends/publishes with partial-completion implications. | Identify each side effect and trace completion/recovery handling. | All inputs are reads, `Promise.allSettled` is used, or each rejection becomes an item result. | One webhook rejects while other deliveries may have completed and retry state cannot identify them. |
