# Operator Content OS

Use this when the question is not "write the post" but "build the machine that keeps producing useful posts and revenue signals."

## Core Thesis

Craft makes the asset. Systems make the asset repeat.

The operating layer has four jobs:

1. Pick the leverage.
2. Turn repeated work into a system.
3. Use content data to choose the next bet.
4. Assign ownership so the work survives busy weeks.

## Three Leverages

| Leverage | Use it for | Risk |
|---|---|---|
| Tools | Speed, automation, editing, analysis, repurposing | Automating unclear judgment |
| Talent | Taste, platform ownership, editing, community, production | Hiring before the process is documented |
| Capital | Paid distribution, contractors, equipment, sponsorships | Spending before the organic signal exists |

Default order: prove manually, document, automate the boring parts, then delegate.

## Four-Stage Systemization

| Stage | Question | Artifact |
|---|---|---|
| Eliminate | Should this still exist? | kill list |
| Document | Can someone repeat it without asking you? | SOP, checklist, template |
| Automate | Can software remove the handoff or reminder? | script, zap, dashboard, prompt |
| Delegate | Can a person own the outcome? | role scorecard, review cadence |

Do not automate taste decisions until the taste standard is documented with examples.

## Content Analysis Loop

Each week, review the last batch and separate four variables:

- **Hook:** first line, thumbnail, first frame, title
- **Format:** reel, carousel, thread, essay, email, teardown, live
- **Topic:** audience problem, belief, desire, objection
- **Illustration:** scene, object, demo, number, visual proof

Change one variable in the next test. Write the hypothesis before publishing:

```text
If we keep the topic and format but rewrite the hook around [specific tension],
then [metric] should improve because [audience reason].
```

## Media Team OS

For a small team, hire around platform ownership rather than vague "content help."

| Role | Owns | Success signal |
|---|---|---|
| Strategist/operator | calendar, through-line, review | fewer random posts |
| Producer/editor | recording, edits, asset packaging | faster publish cycle |
| Platform owner | native format, comments, scheduling | platform-specific lift |
| Community/research | DMs, comments, questions, objections | better idea quality |

Hiring funnel: paid trial on one real asset -> scorecard -> weekly review -> documented handoff. Onboarding stack: brand voice, examples, banned patterns, source library, review rubric.

## Portfolio Execution

For multiple ventures, centralize the system and decentralize the surface:

- Centralize: cadence, metrics, source library, editing standards, review rhythm
- Decentralize: brand voice, offers, visuals, platform choices, examples

One person can run the portfolio if the system forces tradeoffs. Pick the primary platform or venture for the next 30 days; everything else gets maintenance cadence.

## Output Format

Return:

1. Current bottleneck
2. System map
3. Weekly cadence
4. Owner table
5. Metrics and review loop
6. Next 7-day experiment

End with the smallest concrete operating change, not a motivational summary.
