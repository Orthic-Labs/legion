# Alchemist execution

Legion selects capabilities & attaches Alchemist authority before delegation. Alchemist owns
bounded implementation within settled acceptance criteria; capabilities provide method &
expertise. Dispatch carries an assignment already decided by Legion.

## Assignment

Use host-native execution. Choose only model tiers supported by current host; narrow mechanical
work may use its cheap tier. Start delegated work with fresh context & include:

- Raw request plus accepted corrections.
- Settled scope, exact OWN/READ/FORBIDDEN paths & writable allowlists, exclusions, & relevant evidence pointers.
- Expected result, acceptance criteria, root-owned checks, & required delivery state.
- Applicable host or locked-domain constraints.

Ordinary delegation uses an inline assignment. Contracts apply only to host-declared locked
domains or explicitly contracted work. If native execution is unavailable, report that missing
host capability to Legion.

## Implementation & return

Workers edit only within exact allowlists on primary checkout. Bounded read-only inspection
is allowed; Cargo, tests, builds, generators, installs, commits, pushes, merges, heavy checks,
post-merge verification, worktrees, & branches are prohibited. Return changed paths, source
result, remaining work, & exact blockers. Escalate changed requirements, public boundaries, or material tradeoffs to
Legion/Sage. Keep independent assurance with Oracle when requested or justified by concrete risk.

Root integration alone verifies worker output on primary checkout after all coding completes,
then owns commits & delivery. Worker claims alone never prove delivery.
