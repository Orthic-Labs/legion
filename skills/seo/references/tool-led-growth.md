# Free tools as search acquisition assets

Use for calculators, checkers, converters, generators & interactive utilities intended to attract qualified customers. SEO owns demand, SERP fit & measurement; product/engineering owns implementation & business logic, Marketing owns offer terms.

## Select a useful tool

Start with first-party questions & adjacent tool/calculator queries. Provider volume/KD estimates can narrow research; a KD<10 filter is an optional prospecting choice, not a success threshold. Check live results in target market: what task do users need completed, which utilities already solve it, & what useful difference can this product supply?

Compare candidates by qualified demand, product relevance, existing tool quality, implementation/maintenance cost, operating cost & CTA fit. Prefer one tool with a clear path to activation over a large keyword-driven portfolio. Record why it beats a page refresh or existing product improvement.

Candidate record:

`query/cluster | market | evidence/date | intended URL | user task | existing alternatives | useful difference | product fit | CTA | effort/maintenance | operating cost | primary metric | evaluation condition`

## Page & product contract

- Deliver usable output for a real task; explain inputs, units, assumptions, limitations & data freshness where relevant.
- Validate calculations/conversions against independently checked examples through the implementing capability. Never fabricate results, benchmarks or business facts.
- Include enough crawlable text to explain purpose & use, useful examples, accessible controls & recoverable errors. Avoid indexing each input/session/output permutation.
- Set canonical/indexation policy, metadata & contextual links to relevant product/help pages. Select schema only when applicable & supported by visible content; a tool does not automatically need Article or FAQPage.
- Make CTA match completed task & actual next customer need. Record whether value is accessible before signup; test product links, consent/privacy & analytics needed for the intended claim.

## Evaluate & decide

Reuse `operations.md` intervention lifecycle: baseline, hypothesis, deployment identity, primary metric, guardrails & maturity condition. Track discovery impressions/clicks, successful tool use, CTA clicks, activation, qualified leads & revenue as separate steps. Record event definitions & deduplication; distinguish direct conversions from assisted attribution.

Disposition: retain, improve, investigate, retire or scale. Scale only when observed qualified value warrants maintenance/operating cost. Low traffic alone does not justify deletion. A transcript's traffic, revenue or build-time anecdote is not an expected result.
